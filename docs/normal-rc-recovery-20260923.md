## 실제 배포 화면 확인
- 유효 학생 인증을 보안 입력으로 완료.
- 학생 화면의 초급 10문항을 직접 제출. 마지막 제출 직후 기기 저장 안내, 이후 서버 완료 화면.
- DB: 완료 attempt 1건, beginner record 1건, basic 팩 3→4개.
- 보관함의 한 개 개봉과 Enter 공개 확인. DB: basic 팩 4→3개, 카드 1장, 개봉 이력 1건.
- 새로고침 후 초급 완료·10 XP·카드 1장·팩 3개 유지.
- 아직 로그아웃 후 재인증 및 5/15/30명 흐름은 미검증.
- 기존 버전에는 요청별 계측이 없어 로그인·완료·팩 요청 시간을 정확하게 측정하지 못함. 자동화 도구 호출 시간은 게임 속도로 보고하지 않음.
- 발견한 표시 오류: 10문항 완료 결과가 10/12로 표기. 후속 UI 수정 대상으로 보존.

## 이번 수정 파일
- normal-rc-outbox.js: attempt가 없는 카드팩 요청도 같은 ID로 보관/재전송, 확정 개봉 ID 보존.
- normal-rc-client.js: 순서·스피드런·연결고리·지도 제출 큐 연결. 잘못된 배열은 서버의 active 응답을 그대로 적용하며 완료/보상을 만들지 않음.
- normal-rc-packs.js: 팩 요청의 기기 저장, 로그인 세션 변경 후 같은 학생 복구, 중복 클릭 억제, 저장 실패 시 미전송.
- game-api.js: rcMetrics=1일 때만 비밀값 없는 요청 종류/응답 크기/시간/성공 코드를 콘솔에 기록. 기본 동작에서는 계측 로그 없음.
- student-preview.html: 복구 스크립트와 캐시 버전 연결.
- tests/normal-rc-outbox.test.cjs, tests/normal-rc-packs.test.cjs: 장애 복구 회귀.

## 검증 및 한계
- 저장 큐/팩 UI 장애 검사: 2개 파일 통과, 68.6ms (모형 저장소/서버).
- 기존 도메인 트랜잭션 회귀: 396.9ms (메모리 DB).
- 위 수치는 실제 DB 부하/학생 동시 접속 시간 아님.
- 정상 서버 개편 완료/실제 수업 합격 판정 아님.
- 카드·도감·미션 화면별 분할 조회 및 유효 시험 명부로 전체 동시 흐름 검증 미완료.
- 브라우저 데이터 삭제/저장장치 장애는 로컬 보관을 보장하지 못함.

## 운영 목적
성적 평가와 무관한 학습 동기부여·간식 운영용 게임. 추가 해킹 방어 복잡성을 늘리지 않는다. 교사 권한 확인, 학생별 기록 분리, 재시도 중복 방지와 원자적 팩 처리는 유지한다.
